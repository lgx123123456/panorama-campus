# 校园联机与 Android、Windows 互通方案

记录日期为 2026 年 11 月 17 日。Windows 校园联机已加入 Iroh 异地邀请和原有局域网入口。EOS 可用于配置了项目部署的发行版。Android 留到后续版本。

## Windows 首版使用

打开 [Windows 校园异地联机版](openfire/build/Windows校园异地联机/OpenFire.exe)，在主菜单选择「校园联机」。房主点「异地开房」后复制邀请码，朋友粘贴完整邀请并点「用邀请码加入」。等成员进入大厅后，房主点「进入校园」。发给朋友时发送整个游戏目录，保留随附 DLL。

未配置 EOS 的版本由 Iroh 建房。以 `OF-` 开头的邀请包含房主本局的 Iroh 节点公钥。游戏通过公网发现和中继建立连接，并在直连可用时切换。Iroh 公共节点适合小规模试玩，有共享限流，实际延迟受网络路径影响。新房间刚发布时，客户端会自动重试短暂的发现失败。 [Godot Iroh 0.2.0](https://github.com/tipragot/godot-iroh/releases/tag/v0.2.0) · [Iroh 公共中继](https://www.iroh.computer/services/hosting)

同一网络可点「局域网开房」，另一端输入房主 IP 后点「按 IP 加入」。同一电脑开两个实例时 IP 可留空。游戏内按 E 开关楼门，按 Esc 退出房间。

Windows 双进程已通过异地邀请流程。两端通过邀请码进房，验证了角色移动、双向开门和房主退出后的返回。另用 Windows 房主与 WSL 测试端验证实际中继。测试端只放行 DNS 所需的出站 UDP，可靠请求和可丢弃的位置快照都经公网中继传输成功。两台远端 Windows 实机之间的延迟待测。 [双进程测试场景](openfire/tests/campus_lan.tscn)

## EOS 发行配置

EOS 模式使用 EOSG 2.3.1。发行时在 `OpenFire.exe` 同目录放置 `campus-eos.cfg`，开房会使用 EOS 的八位房间码。开发调试可将配置放至 Godot 的 `user://` 目录。到 Epic 开发者后台选择产品与部署，为客户端策略启用 Connect、Lobbies 和 P2P，使用该游戏的客户端凭据。 [Epic 开发者后台](https://dev.epicgames.com/portal/) · [EOSG 2.3.1](https://github.com/3ddelano/epic-online-services-godot/releases/tag/2.3.1)

```ini
[eos]
product_id=""
sandbox_id=""
deployment_id=""
client_id=""
client_secret=""
```

同时给两个测试端传入 `-- --campus-force-relay` 可强制走中继，传入 `-- --campus-direct-only` 可单独验证直连。将这些参数用于测试，正常启动自动尝试直连及中继。Windows 首版联机范围为整校漫游。

## 选型与玩家流程

Windows 首版支持最多四人，由房主的 OpenFire 进程运行对局。Iroh 和 EOS 共用场景加载、玩家同步和楼门逻辑。EOS 模式使用 Lobbies 查找房间，用 EOS P2P 传输数据。P2P 优先尝试直接连接，失败时由 EOS 中继转发。校园碰撞和门状态由房主管理。 [EOS 服务说明](https://onlineservices.epicgames.com/faq) · [EOS 中继策略](https://dev.epicgames.com/docs/en-US/api-ref/enums/eos-e-relay-control)

房主开局后，大家加载校园并从校门出发。房主退出时结束本局，客户端返回主菜单。计划中的 Android 互通使用 EOS 部署，届时 Windows 和 Android 可在同一房间入口输入八位房间码。游戏用 EOS Connect 的设备 ID 在后台完成游客登录。 [EOS 设备 ID](https://dev.epicgames.com/docs/api-ref/functions/eos-connect-transfer-device-id-account?lang=zh-CN) · [EOS 大厅接口](https://dev.epicgames.com/docs/epic-online-services/multiplayer/lobbies-and-sessions/lobby-interface/lobby-interface-reference)

## 接入现有 OpenFire

当前工程使用 Godot 4.6。菜单的 Host 和 Join 已经接入 ENet，大厅开局加载通用 `world.tscn`。校园场景走另一条加载路径，仍以本地的 `Walker` 为中心。现有联机底座可用于建房、玩家生成和状态同步。 [工程配置](openfire/project.godot) · [现有联机入口](openfire/scripts/autoload/net.gd) · [菜单](openfire/scripts/ui/main_menu.gd) · [校园场景](openfire/scenes/campus/campus.tscn)

1. **接入 EOS。** 在 Epic 开发者后台创建产品和测试部署，启用 Connect、Lobbies 和 P2P。固定 EOSG 插件和 SDK 版本。`Net` 的在线路径接入 `EOSGMultiplayerPeer`，使用同一个 `MultiplayerAPI`。同步核对通用断线清理，现有实现只会对 ENet 执行显式关闭。LAN 入口可继续用于本机调试。 [EOSG 仓库](https://github.com/3ddelano/epic-online-services-godot) · [EOSG MultiplayerPeer 源码](https://github.com/3ddelano/epic-online-services-godot/blob/main/src/eosg_multiplayer_peer.cpp)
2. **接入房间码和开局。** 通过 EOS 大厅属性查询房间码，并取得房主身份与 P2P 接入信息。两端进入同一 EOS 部署，并允许 Windows 和 Android 加入。进房时检查人数、协议版本和关卡版本。保留加载完成确认，等成员准备好后由房主生成玩家。房主关闭对局时一并关闭大厅和连接。 [EOS 大厅搜索及权限](https://dev.epicgames.com/docs/epic-online-services/multiplayer/lobbies-and-sessions/lobby-interface/lobby-interface-reference)
3. **接入校园地图。** 把轻量校园场景加入房间的关卡选项，按房间成员生成角色。每台设备采集自己的玩家输入，只启用本地摄像机。地图、模型和贴图随游戏包分发。联机版的动态碰撞加载覆盖所有玩家附近的区域，测试两人分处教学楼和公寓时的楼板与楼梯。 [校园碰撞](openfire/scripts/campus/campus_world.gd)
4. **同步动作与共享状态。** 位置和朝向使用带序号的可丢弃快照，远端插值并丢弃旧快照。开门和对局事件走可靠消息。门使用稳定编号，发送交互请求后由房主检查玩家位置、门锁和门口占用，再广播结果。玩家加入时获取当前门状态。固定插件版本后核对传输模式映射和包大小，避免移动更新堆积。 [楼门交互代码](openfire/scripts/campus/campus_doors.gd) · [插件传输实现](https://github.com/3ddelano/epic-online-services-godot/blob/main/src/eosg_multiplayer_peer.cpp)

## Android 与 Windows 同房

Godot 4.6 可以导出 Android，EOS 的 Lobbies 和 P2P 可用于跨平台连接，EOSG 提供 Windows 和 Android ARM64 构建。两端共用房间协议、RPC 节点路径、关卡坐标及交互对象编号。Android 可使用简化的渲染资源，楼板、楼梯和门洞的通行位置要与 Windows 版对齐。游戏内的房间码界面两端共用。 [Godot Android 导出](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_android.html) · [EOS 跨平台游戏服务](https://dev.epicgames.com/docs/epic-online-services/accounts-and-social/crossplay/crossplay-introduction) · [EOSG 支持平台](https://github.com/3ddelano/epic-online-services-godot)

| 项目 | Android 首版工作 |
| --- | --- |
| 导出 | 现有预设只有 Linux、Windows 和 macOS。新增 Android `arm64-v8a` 预设，配置 JDK 17 和 Android SDK。启用 Gradle，按插件文档纳入 EOS Android SDK，并启用 `INTERNET`、`ACCESS_NETWORK_STATE` 和 `ACCESS_WIFI_STATE`。先导出 APK，在真机验证启动和游客登录。 [导出预设](openfire/export_presets.cfg) · [EOSG Android 配置](https://3ddelano.github.io/epic-online-services-godot/docs/topics/initialization#initialization-on-android) |
| 输入 | 校园控制目前主要使用鼠标和键盘。横屏左侧摇杆用于移动，右侧滑动控制视角，配交互、跳跃及蹲伏按钮。触控和键鼠共用游戏动作，测试同时移动、转向和开门。 [校园控制器](openfire/scripts/campus/campus_walker.gd) |
| 画面与资源 | 桌面工程使用 Forward+。Android 先试 Mobile 渲染器，再按目标设备评估 Compatibility。测试地图先取校门、尚德广场和一段教学楼。当前整校 GLB 约 165 MiB，整校碰撞资源约 40 MiB，两项为工程源文件的磁盘大小。按真机的包体、内存和帧时间决定贴图缩减、模型 LOD 和分区加载范围。 [Godot 渲染器说明](https://docs.godotengine.org/en/4.6/tutorials/rendering/renderers.html) |
| 启动流程 | 校园房间直接使用随包资源。通用 Host 和 Join 当前受本机 ComfyUI 就绪状态控制，校园在线入口应以 EOS 登录和地图加载完成作为进入条件。 [菜单逻辑](openfire/scripts/ui/main_menu.gd) |

## 开发与验收顺序

| 阶段 | 验收内容 |
| --- | --- |
| Windows 双端小场景 | 两台不同网络的电脑分别建房、输码加入、移动、退出和重新开房。用正常策略测试连接，再强制中继验证保底路径。记录实际连接路径、进房耗时、往返延迟和抖动。 |
| Android 加入 Windows 小场景 | 真机装 APK，由 Windows 建房。手机分别用 Wi-Fi 和蜂窝网络加入，验证触控移动、远端动作与退到后台后的断线恢复或重新入房。 |
| 两端进入校园首段 | 手机和电脑在校门见面，沿尚德广场走到教学楼，双方各开一次同一扇门并一起上楼。两人分开进入不同区域后检查碰撞。记录 Android 的启动耗时、峰值内存、帧时间和持续运行表现。小场景和首段通过后，再扩大校园覆盖。 |
