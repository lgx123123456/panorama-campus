# 《上课》发布版界面改版计划

2026年11月17日 · 首轮面向 Windows 桌面版

启动即进入《上课》主菜单。正式游玩以单人校园逃生为主，管理员从独立入口进入测试。此次改版覆盖启动、加载、局内 HUD、暂停、结算及返回流程，沿用现有校园美术、场景加载和关卡逻辑。

## 现状与发布决策

| 已核对的现状 | 发布版做法 |
| --- | --- |
| [首页](openfire/scenes/main_menu.tscn)把 OpenFire 的对战、地图、机器人和校园功能放在一起。项目标题和 Windows 导出元数据也沿用 OpenFire。 | 新建《上课》启动页。统一窗口标题、任务栏图标与发行包名称，OpenFire 等来源保留在制作人员与开源鸣谢中。通用对战和生成配置留在旧开发工程入口。 |
| [首页脚本](openfire/scripts/ui/main_menu.gd)将「校园逃生」接到 [survival.tscn](openfire/scenes/campus/survival.tscn)，当前场景明确开启 `enable_debug_tools`。 | 正式和测试各有明确的场景入口，共用同一套校园与关卡资源。正式入口关闭调试工具，并检查场景属性、快捷键、命令行入口和导出内容。 |
| [现有校园联机](校园联机与安卓互通方案.md)原版本支持最多四人进行校园漫游。第一批将房间容量调为 1–10 人（含房主）。 | 首轮如随包发布，标为「联机漫游」，进入房间页创建或加入；「合作逃生」待实际跑通撤离关卡后再上主菜单。 |
| [关卡脚本](openfire/scripts/campus/campus_zombie_level.gd)在左上常驻操作、丧尸数量和反馈；部分校园场景的 Esc 直接离场。 | 正式版按状态显示提示，Esc 统一进入暂停或会话菜单。调试数据归管理员面板。 |

正式玩法清单以打包前实际确认的内容为准。原方案中的无枪校园与现有可用道具存在差异；入口和界面改版先与实际可用操作对应，公开试玩前冻结正式道具清单，再同步教程和 HUD。

## 启动页

参考[《返校》官方资料](https://redcandlegames.com/presskit/sheet.php?l=en&p=detention)用校舍营造气氛，参考[《求生之路2》官方页面](https://store.steampowered.com/app/550/Left_4_Dead_2/)区分单人和合作体验。主视觉采用石家庄一中东校区正门的实机画面。右侧呈现正门、校名和红灯笼，左侧用暗色渐变托住标题和菜单。首页显示后后台预读校园场景。

```text
上课                             一中东校区正门实机画面
从教室出发，找一条路离开校园。

[ 正式游玩 ]                     单人校园逃生
  联机漫游                       随已验收的联机功能开放
  设置
  退出游戏

  制作人员与开源鸣谢 · 版本号      管理员测试（内部构建）
```

- 「正式游玩」默认聚焦，点击或按 Enter 直接进入单人加载。设置集中显示画质、显示模式、视野、音量和鼠标灵敏度，沿用现有设置保存逻辑。大厅、设置与确认框统一中文文案和键盘焦点顺序。
- 同时保留两条入口，默认交付两个 Windows 构建。正式包提供正式游玩；内部包沿用同一首页，右下角增加「管理员测试」，进入后全程显示「测试模式」标记。测试页集中放逃生关卡、校园漫游点位、人物测试和性能诊断。老 OpenFire 的对战入口继续保留在开发工程内。
- 先做两份导出配置并核对包内内容。公开包通过场景与导出配置隔离管理员能力，内部快捷方式和测试场景随测试包交付。测试模式退出后回到管理员测试页，正式对局结束后回到主菜单。

## 游戏内界面

| 状态 | 设计与交互 |
| --- | --- |
| 加载 | 沿用现有资源进度、准备场景与碰撞、载入视图的实际状态。放一条当前模式的操作提示。失败后有「重试」「返回主菜单」，禁止重复触发加载。 |
| 初入教室 | 左上最多一条目标，例如「离开教室，找一条安全的下楼路线」。首次遇到开门、静步等操作时，显示对应按键；提示随完成或离开触发范围收起。 |
| 正常游玩 | 准星附近显示「E 开门」「E 拾取」等短提示，底部保留生命和当前道具。常驻键位表移到暂停菜单。目标随开局、出楼和撤离状态更新，留出走廊和门边的视野。 |
| 感染或转化 | 受伤与感染出现时显示对应文字和倒计时；转化后更换为角色能力及冷却提示。危险状态同时使用文字或图形表达。 |
| Esc 菜单 | 提供「继续游戏」「设置」「操作说明」「返回主菜单」。单人暂停关卡计时与角色行动；在线漫游打开本地菜单，仍保持房间和同步，退出前确认。关闭菜单后恢复鼠标捕获，菜单打开时屏蔽玩家动作。 |
| 结算 | 根据已有结果显示「成功撤离」或「感染离校」，有可靠数据时显示出校方向和耗时。提供「再玩一局」「返回主菜单」。 |
| 管理员模式 | 保留现有 F6 调试面板与性能信息。明确 Esc 的关闭顺序：先关闭最上层弹窗或调试面板，再处理暂停菜单。使用状态标识区分正式、测试对局。 |

## 实施顺序与验收

| 批次 | 工作 | 当批验收 |
| --- | --- | --- |
| 1：启动页与入口 | 做 1280×720 首页样板、窗口与图标；把既有 `_on_campus` 加载路径供新菜单调用；拆正式与测试场景入口及 Windows 导出配置。 | 默认启动显示《上课》；正式游玩从致远楼教室开局；内部版两条入口都可用。公开包抽查测试热键、旧启动参数及被排除的测试场景。 |
| 2：局内流程 | 新建独立校园 HUD，把关卡脚本已有的状态接到界面；换加载页、Esc 菜单及结算画面，集中处理鼠标捕获和返回状态。 | 真实跑一遍开门、下楼、感染提示、撤离、重玩和返回。分别验证正门与西门结算、反复开关暂停、设置重开后保留，以及管理员退出回到测试页。 |
| 3：发行验收 | 导出候选包，完成 UI 截图、启动与联机检查，整理正式包与内部包。 | 在 1280×720、1920×1080 及 Windows 125% 缩放下检查中文、焦点和界面裁切。用干净目录启动两种包，验证加载失败可返回及多次进出场景。联机若随包发行，双机验证创建、加入、退出和断线回首页，再做 10 人满房和第 11 人拒绝加入检查。 |

交付首页、加载、正常游玩、感染、暂停、结算及管理员页的实机图，另附两个 Windows 构建和各自的验收记录。公开包名用「上课」，内部包和窗口加「管理员测试」标记。

## 第一批交付

Windows 候选构建已将游戏更名为《上课》，封面采用一中东校区正门的夜景实机画面，冷雾压暗远处校舍，门洞保留一盏暖灯。正式游玩从致远楼二层教室开局，管理员版在首页右下角提供测试入口。联机漫游房间上限为 10 人，校门集合点分三排摆放。局内 HUD、正式暂停菜单和结算样式安排在第二批。
