## 一、这个包是什么

一共 4 个部分：

```
D:\资料\全景校园\数据\
├── 01_全景原始\        ← 全景图本体（最高清）
├── 02_元数据\          ← 结构化数据（表格 / JSON）
├── 03_附属资源\        ← 缩略图 / 音乐 / 图标 / 封面

├── 使用说明.md         ← 本文件
└── 3D还原方案_给Codex.md ← 还原路线的技术规格
```

## 三、02_元数据 —— 结构化数据

| 文件 | 内容 | 怎么用 |
|---|---|---|
| `tour_full.json` | 全量元数据：标题、简介、GPS、45 场景（名称/分组/panoId/cdn/初始视角/热点/音乐） | 程序读取 |
| `scenes.csv` | 场景总表，Excel 直接开 | 看清单、筛场景 |
| `hotspots.csv` | 153 条热点：源场景 → 目标场景 + `ath`/`atv` 方位角 | 做导览图 / 定位 |
| `scene_graph.json` | 场景连通图（节点 + 边，`mutual=true` 表示双向都有热点） | 图算法、配准 |

### 几个关键字段

- **`ath` / `atv`**：以该场景自身为原点的方位角（0 = 画面中心，顺时针）和仰角（+上）。
  例：`03 大门口` 有热点 `ath=-0.76, atv=61.5` 指向 `尚德广场` —— 说明广场在大门正前上方。
- **`世界朝向φ`**（`scenes.csv` 最后一列）：每场景相对基准场景的旋转，
  `世界方位 = ath + φ`。基准是把场景 01 的 φ 定为 0，误差约 ±20°。

  > **这个 φ 是相对基准，不是真北。** 但它的**相对关系**经检验可信：同一建筑群的场景 φ 高度一致
  > （图书馆 339.9 / 行远楼 339.7 / 知远楼 340.5；大门口 352.0 / 尚德广场 352.7；
  > 男生公寓 108.6 / 120.6 / 105.2）。所以拿它做场景间配准初值没问题。
  >
  > **定真北的办法**：`04_建模参考\02_八方向\03_大门口\000.jpg` 是校门正面（朝校内）、
  > `180.jpg` 是门外湘江道。若校门朝南（临湘江道），则该场景 `ath=0 ≈ 北`，对应 `φ=352°`，
  > 即 φ 体系与真北差约 **8°**。这只是单点推断，**请再用两三个场景复核**；
  > 若发现整体差 90°/180°，直接改 `manifest.json` 的 `north_offset_deg` 一次性修正即可。
- **`gps`**：`38.032197, 114.632524`（GCJ02），站点"地址导航"里带的真实坐标。
- **`cdn`**：每个场景各自的图片节点编号（134/135 混用），复现抓取时需要。

## 五、04_建模参考 —— 给建模用的参考图（139 MB）

这是这批数据对建模最有价值的部分。

### `01_正射俯视_航拍天底.png`（2600×2600）

从「航拍（正上方）」全景的**天底**反投影出来的真实俯视图 —— 相当于无人机垂直向下拍的一张校园总平面。

图上画了相对方位刻度（30° 一格）。
**注意**：刻度基准是场景 01 的坐标系，**不是真北**。真北需要用图上「湘江道（校园南侧，东西向）」和「秦岭大街（校园东侧，南北向）」两条路来校正。

用途：
- 当 Blender 底图，直接描建筑轮廓、道路、操场
- 量建筑之间的实际距离比例（用 400 m 跑道外圈 = 172×92 m 标定像素）
- 校核你自己画的布局图

### `02_八方向\{NN}_{场景名}\000.jpg … 315.jpg`

每个场景 8 个方位（0/45/…/315°）、FOV 90° 的正视透视图，1400×1400（由最高清立方体面重投影）。

用途：看立面、量比例、贴图源。不需要开全景软件就能看到某个方向长什么样。

### `03_热点指向\*.jpg`

153 张，每张是「站在 A 场景、朝 B 场景的方向看过去」的画面，文件名带方位角：

```
03_大门口__→尚德广场__ath-1_atv62.jpg
```

用途：判断两个地点之间的相对位置、距离感、遮挡关系 —— 建模摆位置时最直接的证据。

### `00_场景联系表.jpg`

45 个场景的缩略总览，一屏看全。

## 六、数据是怎么来的（能复现）

站点前端是 krpano 播放器，全景切片规则藏在页面内联的 `window.__INITIAL_STATE__` 里：

1. **场景清单 / 热点**：页面内联 JSON 的 `data.product.config`
2. **切片模板**：同处的 `xml` 字段，形如
   `.../imgs/%s/l4/%0v/l4_%s_%0v_%0h.jpg`（`%s` = 面 l/f/r/b/u/d，索引从 1 起、2 位零填充）
3. **CDN 域名**：播放器 JS 里 `cdnDomain{N} = https://ssl-panoimg{N}.720static.com`（N = 0~150，**每场景不同**）
4. **附属资源**：缩略图 → `thumb-t.720static.com`，音乐/logo/二维码 → `media-t.720static.com`，热点图标 → `static-t.720static.com`

抓取脚本在 `C:\Users\Lenovo\test\pano720\720yun_grab.py`，对任意 720yun `/t/` 页面通用：

```bash
python 720yun_grab.py "<tour URL>" --out <目录> --mode tiles --level l4 \
       --equirect 8192 --workers 16 --html --prune-tiles
```

## 七、已知限制

1. **场景之间没有世界坐标**。每个全景是独立视点，站点只给了"从 A 看向 B 的角度"，没给距离。距离要靠俯视图或人工标定。
2. **热点方位有 ±20° 误差**（作者手工摆的），别当测量数据用。
3. **航拍那张（正上方）不要做深度估计**，几十米高空单目深度会崩，它只适合出正射底图。
4. **室内场景（教室/宿舍/排练厅）与其他场景无几何重叠**，只能各自建模或人工摆位。
5. 全景图源是 JPEG，放大到 100% 会有压缩伪影。
6. 版权归学校 / 拍摄方，自用、建模练习没问题，公开发布或商用需另行授权。
