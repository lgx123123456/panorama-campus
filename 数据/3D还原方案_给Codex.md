# 3D 还原方案（交接给 Codex 的技术规格）

> 配套数据：`D:\资料\全景校园\数据\`
> 目标：把 45 张全景还原成可用于 Blender 的校园三维模型（体块 + 贴图 + 场景相机）

---

## 0. 一句话结论

**不要指望 COLMAP/SfM 自动重建。** 这批数据是 45 个**独立视点**的全景，站间没有连续视频、没有相机内参、没有重叠序列；把每张全景切成 8 个透视视角再喂 SfM，会因为"同一视点"直接退化。

可行的三条路线，按性价比排序：

| 路线 | 做法 | 适合 | 工作量 |
|---|---|---|---|
| **A 几何标定 + 手工/半自动建模** | 正射俯视定平面、热点方位定朝向、全景立面做贴图 | 要**准确**的校园模型 | 中，最可控 |
| **B 单目深度 + 点云融合** | 全景 → 立方体面 → 深度估计 → 点云 → 配准 → 重建 | 要**真实细节**的局部场景 | 大，效果不确定 |
| C SfM/MVS（COLMAP） | —— | 不适用 | 别做 |

用户已经在 Blender 里做了「校门还原小样」，主线应走 **A**，B 用于补充局部细节（校门、广场、教室）。

## 1. 数据规格（硬约定）

### 1.1 全景图

| 项 | 值 |
|---|---|
| 格式 | 等距圆柱（equirectangular，2:1） |
| 主文件 | `01_全景原始\scenes\{NN}_{场景名}\equirect_8192.jpg`，8192×4096 |
| 坐标系 | 列 0 → 经度 −180°，列 8192 → +180°；行 0 → 纬度 +90°（天顶），行 4096 → −90°（天底） |
| 立方体面 | 同目录 `faces\{l,f,r,b,u,d}.jpg`，`size×size`（6400 / 8704 / 8768 三种） |

**立方体面朝向约定**（OpenGL cube map，已实测与站点一致）：

| 文件 | 轴向 | 说明 |
|---|---|---|
| `f.jpg` | +Z | 前 |
| `r.jpg` | +X | 右 |
| `b.jpg` | −Z | 后 |
| `l.jpg` | −X | 左 |
| `u.jpg` | +Y | 上（天顶） |
| `d.jpg` | −Y | 下（天底） |

面内像素：左上角为 (0,0)，`u = 0.5·(sc/ma+1)` 横向、`v = 0.5·(tc/ma+1)` 纵向（自上而下）。

### 1.2 场景坐标系与方位角

- 每个场景有**自己独立的**坐标系：`ath=0` 是该全景的"画面中心"方向，`ath` 顺时针增大（度），`atv` 为仰角（度，+上）。
- 场景之间没有共享世界坐标，`φ`（`orientations`）给出每个场景相对基准场景的旋转：
  **世界方位 = ath + φ**（mod 360）。
- `φ` 由 98 对"互相指向"的热点做最小二乘解出，**残差 ≈ 20°**，只可用于粗略朝向，不可当精确外参。
- **但 φ 体系很接近真北**：标定验证见下。

### 1.2.1 真北标定（初值，必须复核）

单点推断：`03 大门口` 的 `φ = 352.02°`，其 `04_建模参考\02_八方向\03_大门口\000.jpg`
正是校门正面（`石家庄一中东校区`牌坊，朝校园内），`180.jpg` 是门外湘江道。
若校门朝南（临湘江道），则该场景 `ath=0 ≈ 北` ⇒ **φ 体系相对真北偏差 ≈ +8°**：

```
真北方位角 = ath + φ + north_offset_deg     # north_offset_deg 初值 8.0，见 manifest.json
```

⚠️ **这只是单点推断，不是定论。** 必须用 `09 运动场`、`02 航拍正上方` 再各复核一次。
若发现整体差 90° 或 180°，直接改 `north_offset_deg` 即可全表修正 —— 所有消费方都从
`manifest.json` 读这个字段，不要硬编码。

`φ` 的**相对关系**是可信的（内部一致性检验）：

| 建筑群 | 场景 φ |
|---|---|
| 图书馆区 | 图书馆 339.9 / 行远楼 339.7 / 知远楼 340.5 / 艺远楼 346.7 |
| 校门区 | 大门口 352.0 / 尚德广场 352.7 / 攀桂轩 352.0 |
| 男生公寓 | 绅远楼 108.6 / 大厅 120.6 / 宿舍 105.2 |
| 女生公寓 | 蕙远楼 77.5 / 大厅 92.2 / 宿舍 98.1 |

→ 同楼群内差 < 20°，可放心用于配准初值；绝对朝向靠 `north_offset_deg` 一次修正。

## 2. 路线 A：几何标定建模（主线）

### A1. 定平面与比例
1. 打开 `04_建模参考\01_正射俯视_航拍天底.png`。
2. 用图上「湘江道（校园南侧，东西向）」和「秦岭大街（校园东侧，南北向）」两条路把**真北**转正 → 记下校正角 `θ_rot`。
3. 用 400 m 跑道外圈长度量像素 → 得到 `米/像素`。
4. 在 Blender 里建一个平面，贴上这张俯视图，设好比例，作为**底图**。
   → 所有建筑的平面轮廓、道路、操场直接照底图描。

### A2. 定场景相机位姿
每个地面场景在全景里的位置，靠三件事定位：
1. **横向位置**：在俯视图上找到该地点（大门、广场、楼前）→ 得到 (X, Y)。
2. **朝向 φ**：`scenes.csv` 的「世界朝向φ」列（相对基准；用 `θ_rot` 转成真北）。
3. **眼高**：地面场景取 1.6 m；航拍场景按 `atv` 反推（见 A3）。

Blender 里每场景放一个 **全景相机**（Cycles 的 Panoramic + Equirectangular），焦距无所谓，朝向 = φ + θ_rot，位置 = (X, Y, 眼高)。

### A3. 推建筑高度（不用激光测距）
在任一地面场景的全景里，建筑顶部相对地平线的仰角 `atv_top` 已知（可从 8 方向片目测），
`H ≈ h_eye + D · tan(atv_top)`，其中 `D` 是从俯视图量到的水平距离。
多个场景交叉算同一个楼 → 取中位数，误差可压到 ±1 m。

### A4. 贴图
对每个立面：
1. 在该立面对应的 `02_八方向` 或 `03_热点指向` 片里量 4 个控制点（楼的四角）。
2. 用仿射/透视变换把 equirect 上对应区域拉平（Blender 里用 `UV Warp` 或外部 Python + OpenCV `getPerspectiveTransform`）。
3. 直接当材质贴到体块上。

> 有 6400–8768 px 的面，一栋楼占 1/3 幅面时仍有 2000+ px 有效分辨率，够贴图。

### A5. 验收
- 把 Blender 渲染结果与 `03_热点指向` 里对应的真实透视图并排比对，轮廓偏差 < 5%。
- 用 3 个不同场景看同一栋楼，三个方向都对得上。

## 3. 路线 B：单目深度点云（补细节）

### B1. 每场景出点云
```python
# 伪代码，Codex 按此实现
faces = load_cubemap(scene_dir)              # 6 × N×N，N=2500 或 8768
for face in "f r b l u d":
    depth = depth_model(faces[face])          # Depth Anything V2 / UniDepth，输出相对深度
    depth = align_scale(depth)                # 用地面/已知高度归一
    将 (u,v,depth) 反投影到该面轴向的 3D 点
合并 6 面点云 → scene_cloud.ply（单位米，原点=该场景相机）
```
- 深度模型选 **UniDepth / Metric3D** 这类带度量的，比 MiDaS 省一次尺度标定。
- 平面区域（地面、墙）用 RANSAC 提平面，先拟合地面校正整体倾斜。

### B2. 场景间配准
1. 初始旋转：用 φ 差值（±20°）。
2. 初始平移：用俯视图量出的 (X,Y) 与眼高。
3. 只在**有共同地标**的场景对之间做 ICP（`scene_graph.json` 里 `mutual=true` 的 98 对里，再筛出间距 < 60 m 的）。
4. 不要全图 ICP —— 会漂。

### B3. 融合与网格
- TSDF/泊松融合（Open3D）→ 网格 → 用立方体面重投影纹理。
- 室内场景基本各自独立，不要试图与室外对齐（没有几何重叠，只能靠门洞位置人工摆）。

### B4. 现实预期
- 室外地面场景：能出"半稠密"点云，建筑立面形状可用，纹理需重新投影。
- 航拍场景：**别做深度**（几十米高空，单目深度失效），只用它的天底做正射底图（已生成）。

## 4. 路线 C 为什么不行（省你两天）

- 全景是单视点 360° 投影，切成 8 个透视视角后**光心仍然重合** → 纯旋转，三角化退化，COLMAP 无法求基线。
- 站与站之间没有连续帧，无法做特征跟踪。
- 全景 JPEG 有压缩伪影 + 站点可能做过锐化，特征匹配质量差。
- 结论：SfM 只能给出"每张全景内部的旋转"，给不出"场景之间的位置"。

## 5. 建议的 Codex 任务拆解

按顺序做，每步都有独立可验收的产物：

| # | 任务 | 输入 | 产物 | 验收 |
|---|---|---|---|---|
| 1 | 数据装载器 | `tour_full.json` | `loader.py`：`list_scenes()` / `load_equirect(i)` / `load_faces(i)` | 45 个场景全部能读，尺寸自洽 |
| 2 | equirect↔cubemap 双向转换 | 全景 | `pano.py` | 与 `faces/*.jpg` 逐像素比对，PSNR > 40 |
| 3 | 方位标定复算 | `scene_graph.json` | `orient.py` | 复现 φ，残差 ≈ 20° |
| 4 | 正射底图配准 | `01_正射俯视*.png` + GPS | `base_map.blend` / `base_map.png` | 真北转正，1 px = X m |
| 5 | 场景相机生成 | 俯视图 + φ | `scenes_cam.py` → Blender 里 45 个全景相机 | 位置与底图吻合 |
| 6 | 立面贴图提取 | equirect + 控制点 | `facade.py` | 拉平后的贴图无透视畸变 |
| 7 | （可选）深度点云 | cubemap | `cloud.py` | 点云与体块轮廓重合 |

**每一步都要落盘中间产物**，因为还原过程需要反复回到第 5 步调位姿。

## 6. 容易踩的坑

1. **不要把 φ 当真北。** 它只是相对基准。真北必须靠道路或 GPS 定一次。
2. **各场景 `size` 不一样**（6400 / 8704 / 8768），读 `faces` 前先看 `tour_full.json` 里该场景的 `l4_size`，不要硬编码。
3. **等距圆柱的极点是变形的**，天顶/天底不能直接当纹理用；贴地/贴顶要走立方体面。
4. **热点是人工摆的**，ath 有 ±20° 误差，只用来定大致朝向，不能当精确测量。
5. **同名建筑**：`艺远楼&识远楼` 这类合并命名，在图谱里是一个节点。
6. **Blender 全景相机**要设 `Panoramic → Equirectangular`，并注意 Blender 的 equirect 默认经度起点与本文档一致（列 0 = −180°），若差 180° 用 `Mapping` 节点旋转。
